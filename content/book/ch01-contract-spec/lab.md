## 场景

我们收到两笔看起来相同的请求：`BUY qty=1 @ 60,000`。先不要假设 `qty` 是 BTC。请分别用下面两张教学规格卡解释它们：

| 字段 | 线性规格 A | 线性合约规格 B |
|---|---|---|
| 数量单位 | BTC | 张 |
| 每张面值 | 不适用 | `0.001 BTC/张` |
| tickSize | `0.1 USDT/BTC` | `0.1 USDT/BTC` |
| qtyStep | `0.001 BTC` | `1 张` |
| 结算币 | USDT | USDT |

## 第一步：先解释 qty

1. 规格 A 中，`qty=1` 代表多少 BTC？
2. 规格 B 中，`qty=1` 代表多少 BTC？`qty=3` 呢？
3. 两个订单的价格相同，为什么名义敞口不同？

## 第二步：校验十进制刻度

对规格 A，逐项检查 `price=60,000.05`、`qty=0.0015`；再检查 `price=60,000.0`、`qty=0.010`。写出除以 tick/step 后得到的整数或非整数结果，不要用“看起来精度太多”作为理由。

## 第三步：计算经济含义

1. 规格 A 下买入 `0.01 BTC @ 60,000`，计算名义价值。
2. 价格上涨至 `61,000`，计算线性毛盈亏并写单位。
3. 另建反向规格 C：每张面值 `100 USDT`，以 BTC 结算。持有 3 张，入场价 `60,000`、平仓价 `50,000`，用本章反向合约简化式计算多头盈亏并写出结算币单位。说明为什么不能沿用规格 B 的 `0.001 BTC/张` 来解释 C。

## 第四步：名义价值与版本

沿用正文的最小名义价值 `100 USDT`，逐项检查 `0.001 @ 60,000.1` 与 `0.002 @ 60,000.1`。再把新请求的价格刻度改为 0.5：旧订单保存的 `600,001 ticks` 必须携带什么信息？分别计算误用新 tick 的价格，以及新请求 `60,000.1` 是否能通过校验。

## 第五步：不合法输入与四级掌握检查

1. `qty=0`、`qty=-1`、`price=0` 恰好能整除刻度，能否通过完整校验？说明缺少哪项条件。
2. **回忆**：分别用一句话解释价格刻度、数量步长、面值和结算币。
3. **推导**：从每张面值换算出反向多头盈亏；验证原价平仓时为零、跌价时为负。
4. **应用**：规格 B 买入 3 张，价格从 60,000 涨至 61,000，计算名义价值和毛盈亏。
5. **重建**：从两个人对 `qty=1` 的不同理解，写出最小规格记录、规范化流程和旧单迁移决策。

## 逐级提示

<details>
<summary>提示 1：先看单位</summary>

将 qty 后面的 BTC 或张补回来，面值也必须带币种。暂时不考虑 tick 与 step。

</details>

<details>
<summary>提示 2：检查刻度关系</summary>

除以 tick 或 step，判断商是否为整数；整除不代替正数、上下限和产品状态检查。

</details>

<details>
<summary>提示 3：找跨版本不变的经济含义</summary>

旧单的实际价格应保持 60,000.1；若 tick 变化，原始整数不再能脱离旧刻度解释。

</details>

## 检查答案

<details>
<summary>完成手算后展开答案</summary>

- 规格 A 的 `qty=1` 是 `1 BTC`；规格 B 的 `qty=1` 是 `0.001 BTC`，`qty=3` 是 `0.003 BTC`。
- `60,000.05 / 0.1 = 600,000.5`，价格刻度不合法；`0.0015 / 0.001 = 1.5`，数量步长不合法。`60,000.0 / 0.1 = 600,000`、`0.010 / 0.001 = 10`，两者可通过刻度检查。
- 线性名义价值是 `600 USDT`，毛盈亏是 `10 USDT`。
- 规格 B 的 `qty=1` 在入场价 60,000 时名义价值为 `60 USDT`，规格 A 同量输入则为 `60,000 USDT`。规格 B 的 3 张名义价值为 `180 USDT`，上涨后的毛盈亏为 `0.003 × 1,000 = 3 USDT`。
- 反向简化多头盈亏为 `3 × 100 × (1/60,000 - 1/50,000) = -0.001 BTC`。真实产品公式需依具体合约规则核验。

- 第四步：两个请求名义价值分别为 `60.0001` 与 `120.0002 USDT`，前者不满足最小名义价值，后者通过这项检查。旧整数须携带产品、单位、原 tick 与规格版本；误用新 tick 得 `300,000.5`，新请求 `60,000.1 / 0.5 = 120,000.2` 不是整数，故拒绝。
- 第五步：零/负数量与非正价格不满足本章准入假设，即使整除也应拒绝。反向原价平仓时倒数相减为零；跌价时 `1/P₁ > 1/P₀`，多头盈亏为负。
- 重建的一种可行答案：记录产品 ID、数量单位、计价方式、面值及币种、结算币、tick/step、范围限制、交易状态和版本；读取适用版本后校验正数与范围、刻度和名义价值，保存规范化输入与版本。规格更新时明确旧单保留语义或撤销迁移，不能仅覆盖配置。

</details>

最后解释：若产品规格在订单挂簿期间改变，系统需要记录什么版本，才能在成交和事后审计时保持原始订单语义？
