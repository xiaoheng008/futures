# 实验：订单生命周期与重试

用纸笔或复制下表，模拟 `BUY 0.01 @ 60,000`，假设依次成交 0.004、0.003，再撤销剩余量。本教学接口以账户与 client order ID 为创建幂等键，保存原参数摘要；真实接口须查其 ID 保留期和重试保证。

| 步骤 | 服务端事件 / 客户端观察 | 累计成交 z | 活动余量 l | 已撤销量 c | 服务端状态 | 客户端能否确定？ |
|---|---|---:|---:|---:|---|---|
| 1 | 接受 K-17，分配 O-17；创建响应丢失 |  |  |  |  |  |
| 2 | 第一笔成交 0.004；推送到达 |  |  |  |  |  |
| 3 | 同一 K-17、原参数重试 |  |  |  |  |  |
| 4 | 第二笔成交 0.003；推送延迟 |  |  |  |  |  |
| 5 | 撤销余量；带版本与累计数量的结果到达 |  |  |  |  |  |
| 6 | 第 4 步成交推送迟到 |  |  |  |  |  |

在服务端已接受订单的各行检查 `q=z+l+c`。讨论：同一 ID 改参数、换 ID 用原参数会分别怎样？如何接收迟到的有效成交，同时防止旧订单状态覆盖终态？

最后交换第 4、5 步的服务端生效顺序，重算数量。说明为什么客户端收到撤单成功不能据此把仓位设为零。
