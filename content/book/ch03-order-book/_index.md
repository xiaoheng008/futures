# 问题：谁先成交？

当前卖盘有三张委托：Alice 以 100 卖 2 张，Bo 以 101 卖 1 张，Chen 以 100 卖 3 张。此时 Dana 提交以 100 买 4 张。

不写代码，先回答：成交价分别是多少？Chen 是否能越过 Alice？成交后 Dana 还剩多少？

如果系统只维护“最新价格”和“总买量/总卖量”，这些问题都无法回答。新概念的压力不是“订单簿（**order book**）很常见”，而是撮合引擎（**matching engine**）必须给出确定、可重复解释的成交次序。

# 尝试：从一个无序列表开始

最直接的做法是把所有活动委托放入列表，新订单到达时扫描对手方，找到价格合适的单子并成交。这先解决了“能不能撮合”，却留下三类歧义：

1. 不同价格都可成交时，选择哪一个？
2. 同价有多个委托时，先满足谁？
3. 部分成交后，剩余量应该排在什么位置？

若每次从头扫描，处理成本还会随活动订单数增长。数据结构必须直接表达业务优先级。

# 发现：公平顺序可拆成两个局部顺序

对买方（**bid**），更高买价优先；对卖方（**ask/offer**），更低卖价优先。同一价格档位（**price level**）内，先进入该档的活动委托优先。于是可以把订单簿组织成两侧价格档位，并在每档保留时间顺序。

一笔限价买单的参考处理过程：

下面先假设它是 **GTC（Good Till Cancelled）** 限价单：立即可成交的部分先成交，未成交余量继续留在簿中，直到成交或撤销。IOC、FOK 和 Post Only 对余量或立即成交的处理不同，不能直接套用这条路径。

1. 查看最低卖价；若卖价高于买方限价，停止匹配。
2. 否则取该卖价档位最早的卖单，按双方剩余量较小者成交。
3. 更新双方剩余量；卖单归零则移除，买单归零则完成。
4. 若买单仍有剩余，将其加入买盘对应价格档位的队尾。

对限价卖单做对称处理。这个模型叫价格优先、时间优先（**price-time priority**），同价位通常按先进先出（**First In, First Out, FIFO**）。这是教学基准；现实产品还可能有自成交保护（**self-trade prevention, STP**）、Post Only、IOC/FOK、价格保护、隐藏/特殊订单等规则，需以具体合约市场的当前规则为准。

# 手算发现

把上面的规则逐轮用于 `BUY 4 @ 100`：每一轮只看最优卖价，成交后更新两边的剩余量，再决定是否继续。

处理 `BUY 4 @ 100`：

| 步骤 | 对手卖单 | 成交价 | 成交量 | 买单剩余 |
|---|---|---:|---:|---:|
| 1 | Alice：2 @ 100 | 100 | 2 | 2 |
| 2 | Chen：3 @ 100 | 100 | 2 | 0 |

Bo 的 1 张 @ 101 高于买方限价，不成交。Chen 尚余 1 张。成交顺序同时满足最佳价格和同价先到先得。

这里隐含一个很重要的边界：限价单的价格是成交价格约束，不保证立刻成交；订单可以立即成交一部分，然后把余量留在簿中。市价单则没有用户指定的价格上限/下限，系统必须定义滑点保护或最大可成交范围，避免把一个“尽快成交”请求误解成“任何价格都成交”。

```mermaid
flowchart TD
  I[收到限价买单] --> B[查看最低卖价]
  B --> C{最低卖价不高于买方限价?}
  C -->|否| R[把剩余买量挂入订单簿]
  C -->|是| M[与该价位最早卖单成交 min(双方剩余量)]
  M --> U[更新成交量与双方剩余量]
  U --> D{买单还有剩余?}
  D -->|有| B
  D -->|无| F[买单完成]
```

# 概念：订单簿只是活动委托的索引

订单簿回答“当前有哪些尚未完成的委托可以匹配”，它不是成交历史，也不是账户余额的权威来源。成交发生后，至少要产生可识别的成交事实；订单簿删除了已完成委托，并不意味着系统可以丢掉成交记录。

可观察的公开 API 也有不同层次：Bybit 的公开订单簿流发出 snapshot 和 delta，客户端必须按协议重置/更新本地簿；这描述的是客户端行情重建契约，不足以说明撮合引擎内部数据结构。[Bybit Orderbook WebSocket](https://bybit-exchange.github.io/docs/v5/websocket/public/orderbook)

# 新问题：撮合之后，系统欠下什么账？

撮合确定了成交双方、价格和数量。下一步必须更新两方的资产、费用和仓位。如果一个成交事件重复到达，账户不能再扣一次；如果撮合状态丢失，订单簿也不能凭空复原真实成交。

下一章从“成交只记一次”出发，推导成交事实、账本分录和仓位投影之间的边界。

# 掌握检查

- **回忆**：买方与卖方各自哪种价格更优？同价订单按什么顺序？
- **推导**：Dana `BUY 4 @ 100`，卖盘是 Alice `2 @ 100`、Chen `3 @ 100`、Bo `1 @ 101`。重算每笔成交和最后剩余量。
- **应用**：把 Dana 的限价改为 99，再把 Chen 的到达时间改到 Alice 之前；分别重建成交序列。
- **重建**：从“成交结果必须确定且可解释”推导价格队列、同价时间顺序、部分成交更新，以及订单簿与成交账本的分工。
