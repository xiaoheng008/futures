# 假设

使用线性 BTC-USDT 永续教学模型。Alice 开多 `0.01 BTC @ 60,000`，Bob 开空相同数量和价格；之后 Alice 平仓 `0.01 BTC @ 61,000`，Bob 对应平仓。忽略手续费、资金费和滑点。清算账户作为教学模型中的盈亏对手方。

# 第一步：先从成交事实算仓位

| 事件 | Alice 仓位 | Bob 仓位 | Alice 累计毛盈亏 |
|---|---:|---:|---:|
| 开仓成交 |  |  |  |
| 平仓成交 |  |  |  |

指出每一行是“发生了什么”的事实，还是“当前处于什么状态”的投影。

# 第二步：设计账本批次

为平仓事件设计分录，覆盖 Alice、Bob 和清算对手方。分别写出 `account_id`、`asset`、`entry_type` 和金额方向。按 USDT 汇总，说明你的业务边界是否守恒。

# 第三步：重放事件

把平仓 Fill 再投递一次。先设计唯一键，再说明重复投递时事务如何做到：

- 已经写入的账本不重复增加；
- 仓位投影不重复扣减；
- 客户端推送可重发，但带有相同事实 ID/序号；
- 服务崩溃重启后仍能判断该事件已经处理。

# 第四步：拆分账户数字

分别定义钱包余额、未实现盈亏、权益、可用余额和冻结/占用金额。指出哪些是账本事实，哪些由风险规则计算得出。

# 重建
