# 假设

使用线性 BTC-USDT 永续教学模型。Alice 钱包有 `1,000 USDT`，开多 `0.01 BTC @ 60,000`；Bob 开空相同数量和价格。随后两人先平仓 `0.004 BTC @ 61,000`，再平掉剩余 `0.006 BTC @ 61,000`。忽略手续费、资金费和滑点，盈亏由双方账户之间结算。初始保证金预留另由风险视图计算，不把名义价值当成现货付款。

# 第一步：先从成交事实算仓位

| 事件 | Alice 仓位 | Bob 仓位 | Alice 累计已实现盈亏 | Alice 钱包余额 |
|---|---:|---:|---:|---:|
| 开仓 Fill：`0.01 @ 60,000` |  |  |  |  |
| 部分平仓 Fill：`0.004 @ 61,000` |  |  |  |  |
| 平掉余仓 Fill：`0.006 @ 61,000` |  |  |  |  |

指出每一行是“发生了什么”的事实，还是“当前处于什么状态”的投影。

先独立算出部分平仓的盈亏和剩余仓位，再计算第二笔平仓。说明开仓时 Alice 的 `600 USDT` 名义价值是否应直接从钱包扣除。

# 第二步：设计账本批次

为两笔平仓分别设计分录，覆盖 Alice 与 Bob。分别写出 `account_id`、`asset`、`entry_type` 和金额方向；再按 USDT 汇总，检查双方已实现盈亏是否守恒。说明仓位变化与钱包分录为什么不能共用一个“余额增减”字段。

# 第三步：重放事件

把平仓 Fill 再投递一次。先设计唯一键，再说明重复投递时事务如何做到：

- 已经写入的账本不重复增加；
- 仓位投影不重复扣减；
- 客户端推送可重发，但带有相同事实 ID/序号；
- 服务崩溃重启后仍能判断该事件已经处理。

# 第四步：拆分账户数字

分别定义钱包余额、未实现盈亏、权益、可用余额和冻结/占用金额。指出哪些是账本事实，哪些由风险规则计算得出。

# 重建

删掉表格里的结果，单看交易价格、方向、数量和账户关系，重新推导平仓盈亏及分录方向。
