## 假设

使用线性 BTC-USDT 永续教学模型。Alice 钱包有 `1,000 USDT`，开多 `0.01 BTC @ 60,000`；Bob 开空相同数量和价格。随后两人先平仓 `0.004 BTC @ 61,000`，再平掉剩余 `0.006 BTC @ 61,000`。忽略手续费、资金费和滑点，盈亏由双方账户之间结算。初始保证金预留另由风险视图计算，不把名义价值当成现货付款。

## 第一步：先从成交事实算仓位

| 事件 | Alice 仓位 | Bob 仓位 | Alice 累计已实现盈亏 | Alice 钱包余额 |
|---|---:|---:|---:|---:|
| 开仓 Fill：`0.01 @ 60,000` |  |  |  |  |
| 部分平仓 Fill：`0.004 @ 61,000` |  |  |  |  |
| 平掉余仓 Fill：`0.006 @ 61,000` |  |  |  |  |

指出每一行是“发生了什么”的事实，还是“当前处于什么状态”的投影。

先独立算出部分平仓的盈亏和剩余仓位，再计算第二笔平仓。说明开仓时 Alice 的 `600 USDT` 名义价值是否应直接从钱包扣除。

## 第二步：设计账本批次

为两笔平仓分别设计分录，覆盖 Alice 与 Bob。分别写出 `account_id`、`asset`、`entry_type` 和金额方向；再按 USDT 汇总，检查双方已实现盈亏是否守恒。说明仓位变化与钱包分录为什么不能共用一个“余额增减”字段。

## 第三步：重放事件

把平仓 Fill 再投递一次。先设计唯一键，再说明重复投递时事务如何做到：

- 已经写入的账本不重复增加；
- 仓位投影不重复扣减；
- 客户端推送可重发，但带有相同事实 ID/序号；
- 服务崩溃重启后仍能判断该事件已经处理。

## 第四步：拆分账户数字

分别定义钱包余额、未实现盈亏、权益、可用余额和冻结/占用金额。指出哪些是账本事实，哪些由风险规则计算得出。

## 重建

删掉表格里的结果，单看交易价格、方向、数量和账户关系，重新推导平仓盈亏及分录方向。

## 逐级提示

<details><summary>提示 1：数量和金额分别更新</summary>

开仓建立敞口；平仓数量乘价格差得到已实现盈亏，不是用平仓成交额扣钱包。

</details>
<details><summary>提示 2：重复效果与确认进度分开</summary>

幂等记录应和本账户的分录/投影效果原子提交。已处理时可推进游标，但不能再加金额。

</details>

## 参考解答

<details><summary>展开仓位、分录与重放结果</summary>

| 事件 | Alice 仓位 / BTC | Bob 仓位 / BTC | Alice 累计已实现盈亏 / USDT | Alice 钱包 / USDT |
|---|---:|---:|---:|---:|
| 开仓 | +0.010 | -0.010 | 0 | 1,000 |
| 平仓 0.004 | +0.006 | -0.006 | +4 | 1,004 |
| 平仓 0.006 | 0 | 0 | +10 | 1,010 |

表中事件是事实，仓位、累计盈亏和钱包列是应用事实后的状态。两笔平仓盈亏为 `0.004×1,000=4`、`0.006×1,000=6 USDT`。开仓不扣 600 USDT 现货本金。

| 结算批次 | account_id | asset | entry_type | amount / USDT |
|---|---|---|---|---:|
| J-102 | Alice | USDT | REALIZED_PNL | +4 |
| J-102 | Bob | USDT | REALIZED_PNL | -4 |
| J-103 | Alice | USDT | REALIZED_PNL | +6 |
| J-103 | Bob | USDT | REALIZED_PNL | -6 |

每批按 USDT 汇总为零。本题特意让两人同时开、同时平，毛盈亏相反；真实撮合对手可能在开仓、加仓或平仓，不能要求每笔 Fill 的双方已实现盈亏自然相反。一般系统通过清算对手科目及未结算义务按定义的业务边界对账。

去重键可为 `(fill_id, account_id, posting_type, asset, line_index)`，仓位处理另用 `(fill_id, account_id, position_scope)`。若两者在同一数据库，应将本地效果和去重标记一起提交；若分属服务，分别提交、恢复和对账。重复两笔平仓后仍为钱包 1,010、仓位 0、已实现盈亏 +10，不再产生新金额效果。

钱包余额由已提交资产分录计算；未实现盈亏由仓位与指定价格计算；本题单币种权益为钱包余额加未实现盈亏。冻结/占用与可用余额来自保证金规则，未必是单独资产转移。分配逐仓保证金时，必须说明它是否已包含在钱包总额中，不能再加一次。

更正一笔错误金额应引用原分录提交冲正/补偿，保留原记录和修正原因；不能覆盖原历史。

</details>
