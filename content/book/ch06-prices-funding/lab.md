# 数据

自造一段短行情（价格单位 USDT/BTC）：

| 时刻 | Last | Index | Mark |
|---|---:|---:|---:|
| t0 | 60,000 | 60,000 | 60,000 |
| t1 | 55,000 | 60,020 | 59,980 |
| t2 | 59,900 | 60,010 | 59,990 |
| t3 | 58,000 | 58,500 | 58,300 |

持有 `0.01 BTC` 多仓，入场价为 `60,000`，逐仓权益简化为 `M + q × (P - P0)`，取 `M=100 USDT`，忽略维持保证金率、费用和资金费。

# 任务 A：观察盈亏

对每个时刻，分别用 Last、Index、Mark 计算未实现盈亏。哪条价格序列让 t1 出现最大瞬时亏损？哪条最能反映 t3 的持续下跌？这组自造数据不能说明交易所实际参数，只用来区分价格角色。

# 任务 B：加风险阈值

设本实验的维持保证金阈值是固定 `2 USDT`。分别使用三种价格判断 `M + UPL ≤ 2` 是否成立。为什么一个交易所的 UI 图表价格可能没有触到某价位，但风控仍按另一价格源变化？

# 任务 C：周期结算

令 t2 结算时 Mark=59,990、仓位 0.01 BTC、Funding Rate=+0.01%。计算资金费大小，并分别记入多头、空头与清算/资金转移科目。再让同一个 funding cycle 事件重放一次：如何防止重复扣款？
