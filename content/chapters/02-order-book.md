# 问题

买单 60,000 与卖单 59,900 同时到来，谁和谁成交？如果卖单数量不足，剩余买量放在哪里？

# 尝试与限制

把订单放进一个列表，再线性扫描可以工作；但每次新单都要找最优价格，取消还要定位订单。列表顺序也不能同时表达价格优先和同价时间优先。

# 发现与概念

价格档位按买卖方向组织，同价订单维护先后顺序。限价单到达时，先与对手盘中价格最优且可成交的订单匹配；剩余数量按价格和到达顺序留在簿中。市场单没有价格保护，必须由产品规则限定保护范围或拒绝条件。

这构成一个参考撮合模型，不足以证明某交易所使用特定数据结构或单线程架构。公开的订单簿 WebSocket 协议还揭示另一层问题：客户端收到快照和增量后，要保持序列连续，不能把展示簿误当作撮合权威状态。[Bybit 订单簿流](https://bybit-exchange.github.io/docs/v5/websocket/public/orderbook)

# 实验

给出三张卖单：`100×2`、`101×1`、`100×3`，再提交 `BUY 100×4`。按价格优先、同价先到先得列出成交和剩余订单。然后把第二笔卖单改为 99，观察成交顺序改变。
