# 起点

你只知道：用户希望提交带杠杆的买卖委托，交易所要公平撮合并在损失扩大前管理风险。请在不看前文的情况下，从一张纸开始推导所需能力。

# 重建挑战

1. 定义合约参数、订单输入和拒单原因。
2. 画出订单状态，并保持数量守恒。
3. 从公平匹配需求推出订单簿与撮合规则。
4. 从成交事实推出账本、仓位和幂等边界。
5. 从潜在亏损推出初始/维持保证金检查。
6. 区分价格用途并推导永续资金费结算需要。
7. 设计强平缺口处理及恢复、对账路径。
8. 定义 API 接受确认与 WebSocket 状态推送契约。
9. 加入限流、故障注入和监控，说明优先保护哪些不变量。

# 评估

每项按四个层次自评：能讲明白（回忆）、能推导关键式子（推导）、能处理新情境（应用）、能从基础问题重建关系（重建）。章节完成不代表掌握；若重建卡住，返回触发该抽象的压力重新尝试。
